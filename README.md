# IoT 두더지 게임

Arduino로 서보모터, 택트 스위치, LCD, 부저, LED를 함께 제어해 만든 3단계 두더지 게임입니다.
올라온 두더지를 버튼으로 맞히면 점수가 오르고, 단계가 올라갈수록 두더지가 빨리 바뀌며 마지막 단계에서는 LED가 방해 요소로 켜집니다.

## 하드웨어 구성

| 부품 | 수량 | 역할 | 핀 |
| --- | :---: | --- | --- |
| Arduino UNO | 1 | 메인 보드 | - |
| SG90 서보모터 | 4 | 두더지를 올리고 내림 | D2, D3, D4, D5 |
| 택트 스위치 | 4 | 두더지 타격 입력 | D6, D7, D8, D9 |
| LED + 330Ω 저항 | 4 | 3단계 방해 요소 | D10, D11, D12, D13 |
| 수동형 부저 | 1 | 정답/오답 효과음 | A1 |
| I2C LCD (16x2) | 1 | 점수와 안내 문구 표시 | SDA A4, SCL A5 |

## 게임 규칙

게임을 시작하면 LCD에 3초 카운트다운이 나오고, 각 단계는 20초 동안 진행됩니다.

| 단계 | 두더지 교체 간격 | 특징 | 다음 단계 조건 |
| --- | --- | --- | --- |
| 1단계 | 3초 | 기본 | 20점 이상 |
| 2단계 | 1.5초 | 속도 증가 | 50점 이상 |
| 3단계 | 1.5초 | 무작위 위치에 LED가 켜져 혼동을 줌 | 종료 후 최종 점수 표시 |

- 정답 +10점, 오답 -5점, 부저로 정답과 오답을 다른 소리로 구분
- 조건을 넘지 못하면 LCD에 필요한 점수를 안내하고 게임 종료

## 구현 내용

- **스테이지 함수화:** 단계마다 진행 시간, 두더지 교체 간격, LED 방해 여부만 다르기 때문에 `playStage(진행 시간, 교체 간격, LED 방해 여부)` 함수 하나로 세 단계를 처리
- **시간 처리:** `delay()` 대신 `millis()`로 단계 시간과 두더지 노출 시간을 계산해, 기다리는 동안에도 버튼 입력을 계속 확인
- **중복 판정 방지:** 두더지 하나당 첫 번째 버튼 입력만 판정하고 바로 다음 두더지로 넘어가도록 처리
- **버튼 회로 단순화:** 택트 스위치를 `INPUT_PULLUP`으로 설정해 별도의 풀다운 저항 없이 연결
- **디버깅:** 시리얼 모니터에 두더지 위치, LED 방해 위치, 정답/오답 결과를 출력해 동작을 확인

## 트러블슈팅

### 1. 조립 중 점퍼선이 계속 빠지는 문제

- 문제: 케이스 안에 부품을 넣고 조립하는 과정에서 택트 스위치와 LED에 연결한 점퍼선이 자꾸 빠져 동작이 끊겼습니다.
- 해결: 점퍼선 끝의 피복을 벗겨 부품 다리에 직접 연결해 접촉을 고정했습니다.

### 2. 두더지 개수 변경에 따른 회로와 코드 수정

- 문제: 처음에는 두더지 3개로 회로를 구성했지만, 중간에 4개로 늘리면서 서보모터, 버튼, LED 회로와 코드를 모두 바꿔야 했습니다.
- 해결: 부품을 4개씩으로 늘리고, 코드는 핀 번호를 배열로 관리하고 두더지 개수를 상수(`NUM_MOLES`)로 두어 반복문으로 처리했습니다. 개수가 바뀌어도 상수와 배열만 고치면 되는 구조입니다.

## 향후 보완 사항

- 케이스 설계를 먼저 하고 부품 배치를 계획한 뒤, 브래킷 등으로 서보모터를 고정해 두더지가 더 안정적으로 움직이도록 개선하고 싶습니다.
- 지금은 3단계의 방해 LED가 두더지와 같은 위치에 켜질 수도 있어, 항상 다른 위치에 켜지도록 바꾸면 의도한 난이도에 더 가까워집니다.

## 회고

- 처음에는 회로 연결이 막막했지만 LED부터 하나씩 연결하며 서보모터, 버튼, 부저, LCD를 하나의 시스템으로 통합할 수 있었습니다.
- 하드웨어 조립부터 게임 로직까지 혼자 완성하며, 문제가 생겼을 때 하드웨어와 소프트웨어 중 어디가 원인인지 나눠서 확인하는 방법을 익혔습니다.
